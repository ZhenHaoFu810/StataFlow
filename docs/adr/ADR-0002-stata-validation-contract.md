# ADR-0002: Stata 验证契约

## 背景

项目的核心承诺是“与 Stata 对齐”。若缺乏稳定、可自动化的验证契约，任何实现都只能停留在主观判断层面。

## 决策

- 默认目标版本锁定 Stata 17
- 运行环境使用用户配置的本地 Stata 17 可执行文件
- 使用 Python 驱动 Stata 批处理执行 `.do`
- Stata 结果必须结构化导出，并映射到统一 result schema
- Stata 17 比较器以字段级 diff 作为唯一验收依据
- 默认使用严格比较；统计意义等价只作为受控例外机制

## 备选方案

### 方案 A：人工查看 Stata 输出

缺点：

- 不可扩展
- 不可审计
- 无法进入 CI

### 方案 B：只校验系数

缺点：

- 无法覆盖标准误、自由度、检验统计量等关键差异

## 后果

- 需要专门的 runner、导出脚本和比较器
- 每个命令的开发成本会上升
- 但每个命令的正确性证据也显著增强

## 何时需要重审

- Stata 版本切换
- 结构化导出格式发生重大变化
- 项目转向“近似兼容”而不再承诺字段级对齐
