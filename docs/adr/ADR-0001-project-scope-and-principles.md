# ADR-0001: 项目范围与基本原则

## 背景

用户目标是构建一个可在 Python 中使用、并与 Stata 高度对齐的计量工具包。该目标涉及多个子系统，包括估计器实现、结果对象、Stata 调用、Stata 17 对照验证与扩展路线。如果一开始就按命令逐个零散实现，极易导致内部重复、测试不统一和结果不可审计。

## 决策

- 采用分层内核路线，而不是逐命令堆功能
- v1 只聚焦线性模型核心，而不直接承诺全量计量命令
- 公开 API 采用“Python 原生 + Stata 映射”策略
- 将 Stata 17 视为默认对齐真值来源
- 以 Stata 17 对照测试作为验收中心，而不是以现有 Python 库的一致性作为验收中心

## 备选方案

### 方案 A：逐命令直接复刻

优点：

- 路线直观

缺点：

- 容易重复实现底层逻辑
- 难以统一测试与结果对象

### 方案 B：现有 Python 库包装优先

优点：

- 启动快

缺点：

- 很难达到 Stata 级别对齐
- 底层规则不可控

## 后果

- 前期文档与测试基建投入较高
- 早期可公开命令数量较少
- 长期可维护性、可验证性和扩展性更强

## 何时需要重审

- 如果 v1 线性模型范围无法在可接受时间内落地
- 如果 Stata 17 对照链路在工程上不可维护
- 如果目标用户明确要求 Stata 命令式接口优先于 Python 原生接口
