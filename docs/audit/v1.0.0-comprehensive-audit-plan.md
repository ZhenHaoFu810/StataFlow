## 1. 审查总览

本计划对 StataFlow v1.0.0 (Stable) 进行三个维度的深度审查：

| 维度 | 目标 | 方法 |
|------|------|------|
| **A. 数学与统计正确性** | 确认每个 estimator 的数学实现与 Stata 命令的统计原理一致 | 逐 estimator 审查 VCE 公式、DoF 计算、PSD fix、T-matrix、小样本修正 |
| **B. 代码质量与可维护性** | 识别冗余、臃肿、不一致的实现模式 | 交叉对比 15 个 estimator 文件中的重复代码路径 |
| **C. 真实数据双跑验证** | 在真实金融经济学问题上确认 Python-Stata 完全一致 | 从 Kaggle 等来源设计 10+ 个真实数据实验 |

## 2. 维度 A：数学与统计正确性审查

### A1. VCE 公式审查 — 重点风险项

#### A1.1 小样本修正不一致（跨 estimator 系统性差异）

| Estimator | vce="ols" 修正 | vce="robust" 修正 | vce="cluster" 修正 |
|-----------|---------------|-------------------|-------------------|
| OLS | `sigma2 = rss / (n-k)` | `n/(n-k)` HC1 | `(n-1)/(n-k) * G/(G-1)` |
| FixedEffectsOLS | `sigma2 = rss / (n-k-1)` | — | `(n-1)/(n-k-1)` (无 G 修正) |
| AbsorbingOLS | `sigma2 = rss / df_resid` | `n/(n-k_full)` HC1 | `(n-1)/(n-k_full) * G/(G-1)` |
| IV2SLS | `sigma2 = rss / n` (渐近) | 无修正 (渐近) | 无修正 (渐近) |
| IVAbsorbingOLS | `sigma2 = rss / df_resid` | `n/(n-k_x_full)` HC1 | `(n-1)/(n-k_x_full) * G/(G-1)` |
| GLM (Logit/Poisson) | Fisher information | `(n-1)/(n-k) * G/(G-1)` | `(n-1)/(n-k) * G/(G-1)` |
| PPMLHDFE | Fisher information | `n/(n-1)` (非标准) | 仅 `G/(G-1)`，无 `(N-1)/(N-k)` |

**审查任务：**
- [ ] **A1.1a**: 验证 IV2SLS 使用渐近 VCE (无小样本修正) 是否与 Stata `ivregress 2sls` 默认行为一致。Stata 的默认 `small` 选项是否影响修正？
- [ ] **A1.1b**: 验证 FixedEffectsOLS 的 `(n-1)/(n-k-1)` 修正与 Stata `xtreg, fe` 一致
- [ ] **A1.1c**: 验证 PPMLHDFE cluster VCE 缺少 `(N-1)/(N-k)` 修正是否与 Stata `ppmlhdfe` 一致
- [ ] **A1.1d**: 审查所有 estimator 对 `df_resid` 的计算 — OLS 用 `n-k`，FE 用 `n-k-1`，AbsorbingOLS 用 `n-k-df_a`，GLM 用 `n-k`。确认每个都与 Stata 一致

#### A1.2 PSD Fix 应用范围与层级

当前 PSD fix 仅在三个 HDFE estimator 的 `cov_reported` 层级应用（`absorbing_ols.py:1206/1468`、`iv.py:1492`、`ppmlhdfe.py:459`）。OLS/FE/GLM 完全不使用 PSD fix。

**审查任务：**
- [ ] **A1.2a**: 确认 Stata `reghdfe` 的 PSD fix 操作层级（`omega_meat` vs `cov_reported`）— 阅读 `research/vendor/stata_community/reghdfe/reghdfe.mata` 中的 `reghdfe_fix_psd`
- [ ] **A1.2b**: 确认 OLS/FE/GLM 不使用 PSD fix 是否与 Stata 对应命令一致
- [ ] **A1.2c**: 验证 `fix_psd_reghdfe` 的 slope 子矩阵备份-恢复策略在数学上是正确的（eigenvalue truncation 后恢复 slope 部分保留 OLS 无偏性）

#### A1.3 T-Matrix _cons 恢复与方差

所有 absorbing estimator 使用 T-matrix 将 LSDV 参数空间转换为报告参数空间。`_cons` 的恢复和方差计算是最高风险区域。

**审查任务：**
- [ ] **A1.3a**: 验证 `_cons = mean(y) - x_bar' * beta_x` 公式在所有 estimator 中一致应用
- [ ] **A1.3b**: 审查斜率吸收的 `_cons` 方差 delta-method override (OLS: `x_bar' Cov x_bar + sigma^2/n`)
- [ ] **A1.3c**: 确认 robust/cluster VCE 下 _cons 方差不含 sigma^2/n 项是否正确
- [ ] **A1.3d**: 识别 MAP 路径 _cons 恢复与 LSDV 路径的差异（特别是 MAP `_compute_map_cons_variance` 中的 grand-mean 近似）

#### A1.4 Driscoll-Kraay VCE 数学验证

**审查任务：**
- [ ] **A1.4a**: 验证 Bartlett 核权重公式 `w_j = 1 - j/(L+1)` 与 Stata 一致
- [ ] **A1.4b**: 验证默认带宽 `floor(4*(T/100)^(2/9)) + 1` 与 reghdfe 一致
- [ ] **A1.4c**: 验证 DOF 修正 `(N-1)/(N-k_full) * T/(T-1)` 与 ivreg2 风格一致
- [ ] **A1.4d**: 确认 `df_r = T - 1` 与 Stata 一致
- [ ] **A1.4e**: 跟踪当 `cluster` 与 DK 组合时 `df_a` 的污染（P1 bug，已在 gatekeeper 中修复）

### A3. 特殊数学路径审查

#### A3.1 Probit VCE — 数值 Hessian

`glm.py:Probit._compute_vce` 重写了 VCE 计算，使用有限差分数值 Hessian（而非 IRLS 信息矩阵）。这是唯一一个子类 VCE override。

**审查任务：**
- [ ] **A3.1a**: 验证 Probit 的数值 Hessian 与 Stata `probit` 的 observed information matrix 一致
- [ ] **A3.1b**: 确认 finite-difference step size 是否合适（当前未显式设置，使用 scipy 默认）

#### A3.2 GMM2S 权重矩阵奇异回退

`iv.py:1018-1022` 当 GMM 权重矩阵奇异时回退到 `_fit_gmm2s_residualized`。

**审查任务：**
- [ ] **A3.2a**: 验证回退路径在数学上是否等价于 Stata 的行为
- [ ] **A3.2b**: 检查回退路径是否已通过 golden 测试覆盖（恰好识别 + 过度识别）

#### A3.3 RD Robust 带宽选择器收敛

`rdrobust.py` 实现了 11 个带宽选择器。synthetic 测试中带宽相对误差 < 5%，但在真实数据上可达 10%。

**审查任务：**
- [ ] **A3.3a**: 验证 MSE-optimal bandwidth 准则的数值实现 — `mserd`、`msesum`、`msetwo` 的 pilot bandwidth 和 regularization term
- [ ] **A3.3b**: 验证 CER-optimal bandwidth 的 scaling factor `N^(-1/20)` 应用正确

#### A3.4 IV Weak-Identification 诊断

**审查任务：**
- [ ] **A3.4a**: 验证 Kleibergen-Paap rk Wald F 与 Stata `ivreg2` 一致
- [ ] **A3.4b**: 验证 Stock-Yogo 临界值表 (`_stock_yogo.py`) 完整且正确
- [ ] **A3.4c**: 审查多内生变量 (`k_endog > 1`) 时 `idstat = np.nan` 的未完整实现
