# 项目章程

## 1. 项目目标

Stata2Python 的目标是在 Python 环境中提供一个面向学术研究的计量工具包，使研究者可以在不切换回 Stata 的情况下完成核心实证建模，并获得与 Stata 高度对齐的估计结果、标准误、显著性结论与结果展示。

第一阶段目标不是覆盖尽可能多的命令，而是建立一条可持续扩展的工程基线，使每一个新增命令都可以在机器可验证的框架中被开发、比对和验收。

## 2. 目标用户

- 金融经济学与应用微观研究者
- 当前使用 Python 做清洗、用 Stata 做回归的研究人员
- 需要可脚本化、可测试、可 CI 的计量基础设施团队

## 3. 非目标

以下内容不属于 v1 或项目前期治理阶段的目标：

- 一次性覆盖 Stata 全部命令
- 直接兼容完整 Stata 命令行语法
- 优先追求高性能而忽略 Stata 对齐
- 把 `statsmodels` 或 `linearmodels` 的现有输出直接包装成真值
- 在缺乏双跑测试的情况下声明“已兼容”

## 4. 成功标准

项目被视为达到阶段成功标准，必须同时满足：

- 已实现能力有明确公开 API、结果 schema 与测试门禁
- 每项公开能力都有 Stata-Python 双跑证据
- 新加入代理只阅读文档即可进入工作
- 架构决策、测试标准与阶段任务之间无冲突

## 5. 版本策略

- `v0.x`：架构、测试框架、线性模型基础能力逐步建设
- `v1.0`：完成第一批公开命令的稳定实现与验证
- 主版本升级仅在公共 API 或结果语义发生不兼容变化时触发

## 6. Stata 对齐原则

- Stata 17 是默认目标版本
- 样本剔除、自由度、共线性处理、常数项规则、权重语义、cluster 修正应显式实现
- 若无法逐位一致，必须以书面形式定义“统计意义等价”并将其纳入测试

## 7. 统计意义等价原则

仅在以下条件同时满足时，才允许接受“统计意义等价”而非严格一致：

- 已证明差异来自可解释数值路径差别，而非逻辑错误
- 系数、标准误、检验统计量、置信区间在预设容差内
- 显著性结论与模型判断不变
- 对应测试样例记录了差异来源、容差依据和接受理由

## 8. 治理方式

- 宏观架构师负责维护原则层文档与裁决统计对齐争议
- 执行代理负责按执行手册实施并回填证据
- 所有原则性变化必须通过 ADR

## 9. 第一阶段范围

- Stata runner 最小可用链路
- 统一结果对象 schema
- OLS
- `vce(robust)`
- `vce(cluster)`
- 单向 FE 基础
- 黄金结果测试与回归测试基线
