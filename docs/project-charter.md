# 项目章程

## 1. 项目目标

Stata2Python 的目标是在 Python 环境中构建一个可扩展的 Stata 命令映射平台，而不仅是若干零散对齐的估计器。平台需要同时满足：

- 提供稳定的 Python 原生计量接口
- 提供常见 Stata 命令的兼容映射
- 对每个公开命令给出可追踪的规则来源
- 通过机器可验证框架证明其与 Stata 17 的对齐程度

## 2. 目标用户

- 金融经济学与应用微观研究者
- 当前使用 Python 做数据清洗、用 Stata 做回归与政策评估的研究人员
- 需要可测试、可脚本化、可持续扩展的计量基础设施团队

## 3. 非目标

以下内容不属于当前版本的目标：

- 一次性覆盖 Stata 全部命令
- 兼容完整 Stata 命令行语法解析
- 在缺少双跑证据时宣称“兼容”
- 直接把现有 Python 库结果包装成 Stata 真值
- 把社区命令的历史全部选项一次性搬进稳定 API

## 4. 成功标准

项目在某一阶段被视为成功，必须同时满足：

- 已实现能力具有明确公共 API 与结果 schema
- 每项公开能力都有 Stata-Python 双跑证据
- 每项公开能力都有研究档案，说明其规则来源
- 新执行代理只阅读文档即可进入工作
- synthetic 与真实公开数据两条验证线均已建立

## 5. 产品结构

平台分为四层：

- `core`
  - Python 原生估计器层
- `compat.stata`
  - Stata 命令兼容层
- `research`
  - 手册、源码、规则与数据集研究层
- `validation`
  - synthetic / real-data 双线验证层

## 6. 版本策略

- `v0.x`
  - 基建、线性模型、FE/HDFE、研究层与双线验证框架逐步建设
- `v1.0`
  - 完成第一批高频命令族的稳定交付
- 主版本升级
  - 仅在公共 API 或结果语义发生不兼容变化时触发

## 7. 命令优先级原则

项目默认按命令族推进，而不是零散命令推进。当前优先级为：

1. `Panel / FE / HDFE`
2. `IV / GMM`
3. `Binary / Count`
4. `DID / Event Study Extensions`
5. `Postestimation`

## 8. Stata 对齐原则

- 默认目标版本为 `Stata 17`
- 样本筛选、自由度、共线性、常数项、权重、cluster 修正必须显式实现
- 对社区命令优先研究公开源码
- 对官方内建命令优先研究官方手册、返回值与双跑结果

## 9. 统计意义等价原则

仅在以下条件同时满足时，才允许接受“统计意义等价”而非严格一致：

- 差异来自可解释的数值路径差异，而非逻辑错误
- 关键统计量在预设容差内
- 统计推断结论不变
- 对应样例元数据记录了差异来源、容差依据与接受理由
- 已由架构治理层明确裁决接受

## 10. 源码与研究档案原则

每个新命令进入实现前，必须至少具备以下一项研究基础：

- 公开源码镜像 + 研究档案
- 官方手册/帮助文档 + 返回值 + 对照样例形成的研究档案

没有研究档案，不得进入实现。

## 11. 验证原则

每个新命令默认需要两类样例：

- synthetic / controlled cases
- 真实公开金融或经济学数据样例

仅当两条验证线都建立后，相关命令才允许进入 `done`。

## 12. 治理方式

- Codex 负责维护原则层文档、审查实现、裁决统计争议
- Claude Code 负责按任务卡实施代码、测试与证据回填
- 原则层变化必须通过 ADR
- 任务仍按分块方式推进，不一次性交付整个命令族
