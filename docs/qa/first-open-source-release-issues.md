# 首次开源发布问题清单

本文件按严重度列出当前项目作为“第一次正式开源发布”仍存在的问题，并给出每项问题的影响与修复目标。

---

## Release-blocking

### 1. 无 LICENSE 文件

**现象**

- 仓库根目录没有 `LICENSE` / `COPYING` / `NOTICE` 文件。

**为什么不可接受**

- 没有许可证，就不能清楚界定外部用户的使用、分发、修改权限。
- 这会让“开源”在法律与协作层面都站不住。

**影响范围**

- 所有外部用户
- 所有潜在贡献者
- 所有未来分发渠道（GitHub / PyPI / 镜像）

**修复目标**

- 选择明确许可证（如 MIT / BSD-3 / Apache-2.0 / GPL 等）
- 在根目录新增标准许可证文件
- 在 `pyproject.toml`、README、release 文档中统一许可证表述

### 2. 包元数据不完整

**现象**

- `pyproject.toml` 缺少 `readme`、`license`、`authors`、`classifiers`、`urls` 等关键字段。

**为什么不可接受**

- 首次开源时，wheel / package 元数据是用户和索引站点理解项目的第一入口。
- 当前元数据更像内部实验包，而不是公开可消费包。

**影响范围**

- `pip` 安装用户
- 未来 PyPI 发布
- 包索引和仓库展示

**修复目标**

- 补齐 PEP 621 关键字段
- 让元数据能正确反映 README、许可证、仓库地址、issue 地址和作者信息

### 3. Python 版本要求不一致

**现象**

- README 写 `Python 3.9+`
- `pyproject.toml` 要求 `>=3.10`

**为什么不可接受**

- 用户会按 README 配环境，但安装时失败。
- 这是最典型的首次使用体验断裂。

**影响范围**

- 新用户
- 教学环境
- 自动化安装脚本

**修复目标**

- 二选一并统一：
  - 把 README 提升到 `3.10+`
  - 或确认代码确实兼容 `3.9` 后下调元数据要求

### 4. 错误的 issue / feedback 链接

**现象**

- `docs/release/open-source-alpha-status.md` 当前把反馈问题指向 `anthropics/claude-code`。

**为什么不可接受**

- 外部用户会被导向错误目标。
- 这是发布页上的硬错误。

**影响范围**

- 所有查看 release 文档的用户

**修复目标**

- 替换成正确的仓库 URL / issue URL
- 若仓库尚未公开，先移除错误链接，改成占位说明

## High priority

### 5. 仓库根目录存在明显内部脚本和日志噪音

**现象**

- 根目录有调试脚本、一次性运行脚本、日志文件。

**为什么不可接受**

- 第一次进入仓库的用户无法快速理解哪些文件是正式入口。
- 会削弱仓库专业度。

**影响范围**

- GitHub 首页观感
- 新用户 onboarding
- 外部贡献者理解成本

**修复目标**

- 把临时脚本迁到 `scripts/internal/` 或 `research/scripts/`
- 把日志移出版本控制并加入 `.gitignore`
- 只保留正式入口文件在根目录

### 6. 无 CI/CD 工作流

**现象**

- 没有 `.github/workflows/`。

**为什么不可接受**

- 首次开源缺少公开可验证的稳定性信号。
- 外部 PR 与回归质量难以保障。

**影响范围**

- 外部协作
- 回归风险控制

**修复目标**

- 增加至少一个基础 workflow：
  - lint / import smoke
  - unit tests
  - golden tests（可选分层）

---

## Medium priority

### 7. 顶层模块仍有原型期文案

**现象**

- `src/statapy/__init__.py` 仍保留 `Phase 0 Bootstrap` 文案。

**为什么不可接受**

- 和当前项目成熟度不匹配。
- 影响开源观感。

**影响范围**

- 阅读源码的用户
- 包内文案一致性

**修复目标**

- 更新为正式项目描述

### 8. 内部证据链文档仍有历史漂移

**现象**

- `workspace/current-task/REPORT.md` 一类工作流文件仍保留历史 stale fresh-run 数字尾迹。

**为什么不可接受**

- 不影响外部首次使用，但影响内部审查可信度。

**影响范围**

- 项目治理
- 后续审查轮次

**修复目标**

- 把历史性工作流文件从发布叙事中剥离
- 对外只保留 release-facing 文档

---

## 非阻塞但应持续注意

### 9. 环境警告噪音

**现象**

- 运行 examples / tests 时，`pandas` 会提示本机 `numexpr` / `bottleneck` 版本偏旧。

**为什么不是当前阻塞**

- 不影响功能正确性；
- 但会影响首次运行观感。

**修复目标**

- 更新开发环境
- 或在贡献者文档中说明
