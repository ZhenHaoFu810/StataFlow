# 测试总策略

## 1. 测试框架目标

测试体系不再只验证“数学上看起来差不多”，而要验证：

- 规则是否与来源依据一致
- Stata 与 Python 是否在字段级对齐
- 真实公开数据中是否仍然稳定

## 2. 双线验证

### Line A：synthetic / controlled cases

用于验证：

- 公式与矩阵实现
- 样本筛选
- 共线性
- 自由度
- cluster / FE / HDFE 修正
- 边界情况

### Line B：real public datasets

用于验证：

- 真实金融与经济学数据上的稳健一致性
- 常见研究场景中的默认行为
- 命令在真实噪声与样本结构下是否稳定

## 3. 测试层级

- 单元测试
  - 基础矩阵与 schema 行为
- synthetic 黄金测试
  - Stata 与 Python 双跑
- 真实数据黄金测试
  - 公开数据集上的双跑
- 全量回归测试
  - 防止后续命令破坏已完成能力

## 4. 验收门禁

一个命令从 `ready` 进入 `done`，至少需要：

- synthetic 黄金样例通过
- 至少一个真实公开数据样例通过
- 全量测试通过
- 研究档案完整
- 样例目录与 backlog 状态一致

## 5. 来源绑定

每个命令测试都要标注其规则来源：

- `source-backed`
  - 对应公开源码镜像
- `manual-backed`
  - 对应官方手册与返回值研究

## 6. 报告要求

失败时必须输出字段级差异，而不是只给出断言失败。

报告至少应包含：

- 命令
- 数据集
- 对齐字段
- 差异字段
- 当前规则来源
- 是否需要 Codex 裁决
