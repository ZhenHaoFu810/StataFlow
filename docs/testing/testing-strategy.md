# 测试总策略

## 1. 测试目标

测试的目标不是证明 Python 实现“看起来合理”，而是证明其与 Stata 在已承诺范围内具有可审计的对齐证据。

## 2. 测试分层

### 单元测试

覆盖：

- 设计矩阵构造
- 样本掩码生成
- 常数项插入规则
- 共线性识别
- robust 协方差计算
- cluster 协方差计算
- FE 残差化

要求：

- 每个数学组件都有独立测试
- 不依赖 Stata 即可运行

### 黄金结果测试

覆盖：

- 同一输入数据下，Python 与 Stata 双跑结果的字段级比较

要求：

- 每个公开命令和关键选项至少一个黄金样例
- 黄金样例必须保存数据、Stata `.do`、期望比较配置

### 回归测试

覆盖：

- 历史 bug
- 曾出现数值偏差的边界情况
- 自由度、cluster、权重与 FE 的脆弱点

要求：

- 修复 bug 时必须追加回归测试

## 3. 比较粒度

双跑比较器至少比较以下字段：

- `params`
- `bse`
- `tvalues`
- `pvalues`
- `cov`
- `nobs`
- `df_model`
- `df_resid`
- `rank`
- `rss`
- `tss`
- `mss`
- `rmse`
- `r2`
- `r2_adj`
- `f_stat`
- `f_pvalue`

## 4. Diff 报告格式

失败时必须输出字段级报告，至少包含：

- 字段名
- Python 值
- Stata 值
- 绝对误差
- 相对误差
- 判定结果

禁止只返回简单断言失败而不说明差异位置。

## 5. CI 门禁

以下条件未满足时不得合并阶段成果：

- 单元测试通过
- 新增黄金结果测试通过
- 旧黄金结果测试无回归
- 文档与测试样例目录已更新

## 6. 新命令准入规则

每新增一个命令或一个重要选项，必须先完成：

1. 在 `docs/backlog.md` 登记
2. 在 `docs/testing/test-case-catalog.md` 预登记测试样例
3. 在阶段执行手册中加入任务
4. 先新增 Stata 双跑测试
5. 再编写实现

## 7. 容差与统计等价

- 默认以严格浮点容差比较
- 如需使用统计意义等价，必须由样例元数据显式声明
- 未声明的字段一律按严格标准执行
