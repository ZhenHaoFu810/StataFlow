# Phase 0 执行手册：Bootstrap

## 目标

初始化项目骨架、测试框架、Stata runner 最小链路和第一条 OLS 双跑样例，使项目具备最小可验证能力。

## 前置条件

- 已阅读项目章程和架构文档
- 本机可访问 Stata 17
- 目标能力已在 backlog 中登记

## 任务序列

### 任务 1：初始化项目骨架

需要完成：

- 建立 Python 包目录
- 建立测试目录
- 建立 Stata 样例与导出目录
- 建立最小依赖管理配置

需要新增的测试：

- 无功能性测试
- 可增加 smoke test 确认包可导入

验收标准：

- 包结构清晰
- 测试框架可运行

禁止事项：

- 不要在此阶段实现完整估计器

### 任务 2：建立 result schema 骨架

需要完成：

- 定义结果对象数据结构
- 实现序列化与反序列化接口
- 预留 Python 与 Stata 的 provenance 字段

需要新增的测试：

- schema round-trip 测试

验收标准：

- 结果对象可稳定导出与读取

禁止事项：

- 不要把 summary 格式和 schema 混为一体

### 任务 3：建立 Stata runner 最小链路

需要完成：

- 检测 Stata 可执行文件
- 生成最小 `.do`
- 执行 Stata
- 收集退出状态与输出文件

需要新增的测试：

- runner smoke test

验收标准：

- 能成功执行一个最小 Stata 脚本

禁止事项：

- 不要在 runner 中硬编码具体模型逻辑

### 任务 4：创建首个 OLS 黄金样例

需要完成：

- 准备最小数据样例
- 编写 Stata `.do`
- 从 Stata 导出结构化结果
- 编写 Python 侧比较测试

需要新增的测试：

- `p0_min_ols_auto`

验收标准：

- 第一个字段级双跑测试通过

禁止事项：

- 不得只比较系数而忽略标准误和自由度

## 阶段验收标准

- Stata runner 可用
- result schema 稳定可用
- 至少一条 OLS 双跑样例通过
- 文档已回填真实路径和证据
