# Open Source Scope Audit

This document records the explicit open-source boundary decisions for the StataFlow project. It is the authoritative reference for the `open_source_manifest.yml` export rules.

**Principle:** `StataFlow` (main repo) is the sole maintenance source. `StataFlow_open_source` is a reproducible export target. No file should exist in the open-source repo unless it is either (a) explicitly whitelisted here or (b) generated by the export script itself.

---

## Audit Method

1. Compared every file and directory between `StataFlow` and `StataFlow_open_source`.
2. Examined test dependencies to determine which data files are required in CI.
3. Evaluated each directory against the criteria: public-facing documentation, required for package functionality, required for CI tests, or internal development material.

## Whitelist and Blacklist Principles for Manifest

### Whitelist (Explicit Inclusion)

The manifest operates primarily on a whitelist. Every path that enters the open-source repo must be explicitly listed or matched by a whitelist rule.

Whitelist categories:
- Root-level standard files (`README.md`, `LICENSE`, `pyproject.toml`, `.gitignore`)
- Entire open subdirectories (`src/`, `examples/`, `docs/architecture/`, etc.)
- Specific files within mixed directories (`docs/operations/open-source-scope-audit.md`, `docs/operations/open-source-export.md`)
- Specific data files required by tests (`tests/data/rdrobust_senate.dta`)

### Blacklist (Explicit Exclusion)

Blacklist rules are applied **after** whitelist copying. They catch generated artifacts and secrets that might be accidentally created in whitelisted directories.

Blacklist categories:
- Secrets and credentials (`Pypi token.txt`, any file matching `*token*`, `*secret*`, `*credential*`)
- Build artifacts (`dist/`, `__pycache__/`, `*.egg-info/`, `.pytest_cache/`)
- IDE and editor metadata (`.vscode/`, `.idea/`)
- Internal AI workspace (`.qwen/`)
- Generated Stata outputs (`stata/output/`, `*.log`, `*.txt` inside `stata/`)

### Default Posture for New Files

If a new file is added to the main repo in a directory that is **not** explicitly whitelisted, it must be treated as **closed by default**. This prevents accidental leakage of internal material.

Conversely, if a new file is added to an explicitly whitelisted directory, it is automatically included unless caught by a blacklist rule. This is acceptable for directories like `src/stataflow/` where all code is intended to be open.

## Test Dependency Map

The following table maps non-golden tests to their external data dependencies, confirming what must be present in the open-source repo for CI to pass:

| Test File | Data Dependency | In Open Source? |
|-----------|----------------|-----------------|
| `tests/test_rdrobust.py` | `tests/data/rdrobust_senate.dta`, `tests/data/rdrobust_senate_with_z.dta` | Yes |
| (all other non-golden tests) | `research/data/public/` datasets | Yes |

No non-golden test depends on `stata/output/`, `stata/cases/`, `tests/golden/`, or internal docs.
