# Open-Source Export Mechanism

This document describes how the StataFlow main repository is exported to the `StataFlow_open_source` mirror.

**Principle:** `StataFlow` (main repo) is the sole maintenance source. `StataFlow_open_source` is a reproducible export target. No file should exist in the open-source repo unless it is either (a) explicitly whitelisted in the manifest or (b) generated by the export script itself (e.g., `.git`).

---

## Files

| File | Purpose |
|------|---------|
| `scripts/release/open_source_manifest.yml` | Whitelist and blacklist rules that define the open-source boundary. |
| `scripts/release/export_open_source.ps1` | PowerShell export script that reads the manifest and synchronizes the target repo. |
| `docs/operations/open-source-scope-audit.md` | Authoritative per-directory open/closed decisions that inform the manifest. |

---

## Running the Export

```powershell
# Preview what would change (no modifications)
.\scripts\release\export_open_source.ps1 -DryRun

# Execute the export (default target: ../StataFlow_open_source)
.\scripts\release\export_open_source.ps1 -Force

# Use a custom target path
.\scripts\release\export_open_source.ps1 -Force -TargetRoot "D:\\repos\\StataFlow_open_source"
```

The script:
1. Reads `open_source_manifest.yml`.
2. Resolves all whitelisted files (root files, specific files, test wildcards, recursive directories).
3. Applies blacklist patterns to exclude secrets and generated artifacts.
4. Copies new or changed files into the target.
5. Removes target files that are no longer whitelisted.
6. Removes empty directories.

---

## Manifest Format

### Whitelist sections

- `files` — Root-level files (e.g., `README.md`, `LICENSE`).
- `directories` — Fully open subdirectories copied recursively (e.g., `src/stataflow/`, `examples/`, `docs/architecture/`).
- `specific_files` — Individual files inside otherwise mixed directories (e.g., `docs/operations/open-source-scope-audit.md`).
- `data_directories` — Public data and validation evidence (e.g., `research/data/public/`, `research/results/validation/`).
- `test_files` — Wildcard patterns for non-golden test files (e.g., `tests/test_*.py`).

### Blacklist sections

- `patterns` — Applied **after** whitelisting. Matches are excluded from export. Includes secrets (`*token*`, `*secret*`), build artifacts (`dist/**`, `__pycache__/**`), and internal directories (`.qwen/**`, `workspace/**`).

---

## Default Posture for New Files

If a new file is added to the main repo in a directory that is **not** explicitly whitelisted, it is treated as **closed by default**. This prevents accidental leakage of internal material.

If a new file is added to an explicitly whitelisted directory, it is automatically included unless caught by a blacklist rule.

---

## Updating the Manifest

When adding new public-facing directories or files:

1. Update `docs/operations/open-source-scope-audit.md` with the decision and rationale.
2. Add the corresponding path to `scripts/release/open_source_manifest.yml` in the appropriate whitelist section.
3. Run a dry-run export to verify.
4. Commit both the audit doc and the manifest changes.
