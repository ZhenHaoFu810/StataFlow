# 阶段门禁

## 1. 总原则

任何命令、选项或阶段只有在通过所有门禁后，才可以被视为完成并进入下一步。

## 2. 三道核心门禁

### 结果审查门

通过条件：

- Python 与 Stata 双跑成功
- 所有承诺字段均被比较
- 无未解释差异

失败时处理：

- 停止扩展下一个能力
- 先补差异分析与修复

### 数值偏差审查门

通过条件：

- 默认严格比较通过
- 如使用统计等价模式，已获得明确批准并记录原因

失败时处理：

- 不得用“差不多一致”作为放行理由
- 必须补写样例分析或 ADR

### API 演化审查门

通过条件：

- 公共参数、返回字段、summary 行为与文档一致
- 无未记录的兼容性破坏

失败时处理：

- 停止发布或推进下一阶段
- 先修正文档或实现

## 3. 阶段推进门槛

进入下一阶段前必须满足：

- 上一阶段所有 P0/P1 条目已完成
- 对应阶段文档中的验收标准均满足
- 回归测试无失败
- 未决 ADR 为零或明确不阻塞

## 4. 新命令进入开发的前置门

必须同时满足：

- 已登记 backlog
- 已登记测试样例
- 已存在阶段任务手册
- 已确认不超出当前阶段范围

缺一不可。

## 5. 例外处理

任何例外都必须：

- 以文档形式记录
- 指明例外原因与影响范围
- 指明何时回补

未记录的例外视为违规。

## 6. 单轮任务完成定义

一个开发轮次只有在以下条件全部满足时才算完成：

- 对应任务卡中的代码工作已完成
- 对应测试已新增或更新
- Python 侧验证通过
- Stata 双跑验证通过，或已记录获批的统计等价
- QwenCode 已提交结构化回报
- Codex 已完成审查并更新 backlog、样例目录或阶段状态

## 7. 必须返工的情形

出现以下任一情况，当前轮次必须返工，不得推进下一项：

- 缺少 Stata 双跑证据
- 只报告“结果差不多”但无字段级 diff
- 修改了公共 API 但未更新文档或未走 ADR
- 修改了原则层文档但未经批准
- 测试通过但未覆盖本轮新增能力

## 8. 允许推进下一项的条件

只有在以下条件满足时，Codex 才可以从 backlog 中放行下一项：

- 当前轮次已满足“单轮任务完成定义”
- 当前阶段没有未解释的高优先级偏差
- 新任务所需前置能力均已稳定
- 对应阶段手册与测试目录已同步更新
